# Завершение диалога и действия с корзиной

Состояние `active/completed` и время завершения хранятся в `sessions`. Миграция `0003_plain_harrier.sql` добавляет два поля; история и корзина сохраняются. Срок жизни текущей сессии остаётся 7 дней.

`finish.outcome=needs_input` означает конкретную недостающую информацию или выбор подготовленного предложения. `complete` означает достаточный результат: готовый текст электрику, объяснение или выполненную задачу. Сервер убирает подсказки для завершённого ответа и отклоняет типичные навязчивые предложения дополнительных редакций. Это ограниченные языковые правила и инструкции модели, не универсальный классификатор.

После завершения UI показывает итог и «Продолжить разговор». `POST /api/conversation/resume` возвращает ввод; `POST /api/conversation/complete` завершает вручную. `POST /api/chat` для завершённого разговора возвращает 409. Оба перехода сохраняют сообщения, корзину и контекст. Новый независимый список чатов в эту доработку не входит.

## Инструменты корзины

| Инструмент | Действие | Проверка на сервере |
|---|---|---|
| `read_cart` | Состав, сумма, показанные предложения | Только текущая cookie-сессия |
| `prepare_cart` | Подготовить один товар и количество | Свежие цена/остаток; не меняет корзину |
| `prepare_solution` | Подготовить полный комплект | Проверенные данные и покрытие всех потребностей |
| `apply_cart_selection` | Применить уже показанный товар/комплект | Явный выбор, ID из последнего предложения, принадлежность сессии, срок и повторная проверка API |
| `set_cart_quantity` | Задать абсолютное количество; 0 — удалить одну позицию | Явная команда, однозначная ссылка на существующий товар, точное количество; свежая цена и остаток при ненулевом количестве |

«Да» непосредственно после предложения одного товара подтверждает его. После обычного вопроса консультанта это обычный ответ. Для двух комплектов недостаточно общего «да»: нужен конкретный вариант. Разговорные «беру тот, что дешевле» и «добавь выбранные товары» (если вариант один) разрешаются моделью по сохранённому предложению. Отказ, условная формулировка и вопрос не дают права изменять корзину. Неоднозначные ссылки при нескольких позициях требуют уточнения.

Добавление использует существующие атомарные операции D1 и токен операции: повторное подтверждение не удваивает количество. Повторное применение ранее выполненного предложения сообщает о повторе; для дополнительного количества нужно явно изменить количество или создать новое предложение. Успешное действие возвращает серверную квитанцию напрямую и завершает цикл модели: дополнительный генеративный ответ не может потерять или переиначить результат действия. Ошибка изменения возвращается без заявления об успехе.

API реальной корзины и заказа ekt.kz не предоставлен. Все операции относятся к корзине этого проекта. Нет оплаты, резервирования и оформления заказа. Кнопка перехода на ekt.kz не переносит корзину.

## Проверки

- `tests/conversation.test.mjs`: разрешения, отказы, однозначный выбор, завершённые ответы, чтение перед изменением, серверные квитанции и ошибки.
- `tests/conversation-integration.py`: изолированные локальные сессии, реальные EKT API и OpenAI; согласие на товар, повтор без дубликатов, изменение/удаление, завершение/возобновление, готовый текст электрику, естественный выбор комплекта и отказ от добавления.
- `tests/solutions-integration.py`: повторные параллельные запросы, изоляция, целостность всего комплекта, изменившиеся цены/остатки, истёкшие предложения.
- Браузер: завершение, сохранение после перезагрузки, возобновление с прежней историей. Небольшая проверочная выборка не гарантирует идеальное понимание любых фраз.

Инструменты используют строгие схемы Responses API, исполняются сервером и проверяются независимо от модели: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/function-calling).
