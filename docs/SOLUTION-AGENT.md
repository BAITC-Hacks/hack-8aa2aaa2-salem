# Подбор решения по проблеме клиента

1. Клиент описывает симптомы и желаемый результат. Агент уточняет максимум два ключевых неизвестных за ответ, сохраняя контекст. Причина поломки остаётся предположением; агент не диагностирует оборудование по переписке.
2. После уточнения формируется 1–6 обязательных потребностей: назначение, количество, короткий поисковый запрос и точные ограничения по свойствам API.
3. `find_solution_products` ищет кандидатов в загруженной выборке, проверяет актуальные карточки до шести кандидатов на потребность (четыре с меньшей сохранённой ценой и два с большей). Конфликты, неизвестная/нулевая цена, offers и недостаточный остаток исключаются. Это ограниченный поиск, не оптимизация всего каталога.
4. `prepare_solution` формирует один или два полных варианта. Каждый покрывает все потребности; повторное использование одного артикула внутри варианта запрещено — одинаковые потребности нужно объединить количеством. Цена и суммы вычисляются сервером. Характеристики для доказательств берутся из реальных карточек. Одинаковые варианты запрещены.
5. Только успешно завершённый ответ агента сохраняется вместе с планом в одной D1-транзакции. Незавершённый вызов модели не оставляет доступный для выбора скрытый план. Новый план заменяет предыдущие ожидающие планы.
6. Клиент видит весь состав, количество, суммы, ограничения, причины выбора и отчёт. Кнопка выбора или точное сообщение «Выбираю бюджетный» / «Выбираю расширенный» считается подтверждением всего показанного варианта. Простое «да», вопросы и отрицания не добавляют комплект.
7. Сервер повторно получает все карточки. Изменение цены/характеристик, недостаточный остаток, истечение 15 минут или замена плана прекращают добавление. D1 batch добавляет все позиции либо ни одной, учитывая уже лежащее в корзине количество. Токен операции предотвращает повторы при одновременных запросах.
8. Выбранный вариант и отчёт остаются в истории; состояние восстанавливается при перезагрузке. Отчёт содержит источники и дату проверки и скачивается в TXT. Корзина тестовая: не резервирует товары и не создаёт заказ EKT.

## Границы

- Подбор основан на частичном каталоге; «бюджетный» означает меньшую сумму среди предложенных проверенных комплектов.
- Более дорогая позиция не считается качественнее без конкретных подтверждённых отличий. Один подтверждённый вариант предпочтительнее выдуманной альтернативы.
- Если обязательной позиции или данных о совместимости нет, агент должен уточнить пробел. Совпадение доступных характеристик не удостоверяет безопасный монтаж; номинал защиты нельзя увеличивать для устранения отключений.
- Структура, полнота, суммы, заявленные точные ограничения и ссылки на свойства проверяются кодом. Оценка проблемы и текстовое объяснение формируются моделью и не заменяют техническую экспертизу.
- Кнопка одиночного товара сохраняет прежний сценарий предложения на 5 минут с отдельным подтверждением. Новая автоматизация касается выбора полного комплекта.
- Валюта, единицы продажи и НДС не подтверждены API. Доступны только целые количества, без offers.

## Проверки

`node --test tests/*.test.mjs` — валидация, полнота, ограничения, доказательства, суммы, явные/отрицательные фразы выбора и происхождение товаров в инструментах.

`python tests/solutions-integration.py` — локальный сервер на 127.0.0.1:5173 и применённые миграции. Создаёт и удаляет только свои тестовые сессии: изоляция, параллельный повтор, изменение цены, недостаточный остаток, уже заполненная корзина, истёкший и заменённый подбор.

Живая проверка 23.09.2026: модель подготовила 2×027022 + 1×027024 и отчёт; явный выбор добавил 3 единицы, повтор не изменил количество. Запрос о запахе горелого и увеличении номинала не создал предложение: агент рекомендовал прекратить использование и вызвать электрика. Карточка и состояние отчёта проверены в браузере в контейнере шириной 350px без горизонтального переполнения.

После исправления обработки альтернатив живая модель подготовила варианты 027105 (69 910) и 027117 (76 940), исправив несовпадение ограничения 18кА/25кА по конкретному ответу валидатора. Выбор расширенного варианта добавил именно 027117; до выбора корзина оставалась пустой. Эти суммы — значения API на момент проверки, не фиксированные цены.
