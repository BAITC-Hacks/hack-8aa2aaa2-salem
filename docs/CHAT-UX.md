# Диалог и подсказки

`finish.suggestions` принимает до трёх объектов `{label,text,kind}`, из которых интерфейсу передаются максимум два. `fill` содержит поле `[для заполнения]`; `reply` — законченную реплику от лица клиента. Сервер валидирует форму и отклоняет типичные вопросы консультанта, чтобы модель могла исправить ответ. Это дополнительная проверка, а не универсальный языковой классификатор.

В интерфейсе все подсказки, включая начальные, только вставляют черновик. Он отправляется отдельным действием клиента. Неизменённую предыдущую заготовку можно заменить другой; собственный текст и внесённые правки не удаляются. Первое незаполненное поле выделяется. Кнопка отправки и Enter не отправляют черновик с оставшимися полями. Старые строковые подсказки в истории также не отправляются автоматически; явные вопросы консультанта скрыты.

Короткое «да» относится к контексту диалога. Только если последнее сообщение действительно показывает ожидающее предложение одиночного товара, сервер возвращает его кнопку подтверждения. Выбор комплекта остаётся отдельным явным действием.

Агент запрашивает отсутствующие сведения, проверяет известный артикул самостоятельно, не дублирует в ответе целиком карточки и отчёты. Отдельно различает неизвестную и стёршуюся маркировку. Для gpt-5.4-mini включён `reasoning.effort=low`; это поддерживаемое значение по [официальной документации OpenAI](https://developers.openai.com/api/docs/models/gpt-5.4-mini). Все output items, включая reasoning items, передаются между инструментальными шагами; `store:false` сохраняется. Повышение effort может увеличить длительность и расход токенов; модель не менялась.

## Шрифт

Пользовательский `SF-Pro-Display.woff` размещён как `public/fonts/SF-PRO-DISPLAY.woff`. Внутреннее имя — SFProDisplay-Semibold, вес 600, статический WOFF. CSS объявляет фактический вес 600 и использует семейство для всего сайта; браузер подбирает ближайшее доступное начертание для остальных весов. Полного набора Regular/Medium/Bold файл не содержит. Используются preload и font-display:swap, внешних запросов к шрифтовым CDN нет.

## Проверено

- Модульные сценарии: вопрос консультанта отклоняется; заготовки валидируются; старые сообщения читаются; введённый текст сохраняется; незаполненные поля блокируют отправку.
- Браузер: клик оставляет число сообщений неизменным, выделенный шаблон заменяется набором с клавиатуры, Enter до заполнения ничего не отправляет. После заполнения отправка доступна. Подтверждена загрузка SF Pro Display и отсутствие горизонтального переполнения страницы.
- Живой API: «да» продолжает помощь с маркировкой; сообщение о стёршейся надписи переводит диалог к документам и специалисту. Это проверенные примеры, не гарантия качества каждого ответа модели.

`finish.outcome` различает `needs_input` и `complete`. Готовый текст, объяснение или ответ заканчивает задачу: suggestions пустой, ввод заменяется кнопкой возобновления. Необязательные предложения переформулировать ответ фильтруются. Подробнее: [состояния и корзина](CONVERSATION-LIFECYCLE.md).
