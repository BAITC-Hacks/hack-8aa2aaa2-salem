## Изменения в приложении

- В карточках видна дата получения данных; сохранённые ответы не выдаются за новую проверку.
- При открытии товара и подтверждении корзины выполняется запрос к EKT. Ошибки не подменяются данными из кэша с пометкой «сейчас».
- Новые снимки имеют приоритет над старыми независимо от таблицы хранения.
- Неизвестная/некорректная цена сохраняется как `null`, ноль обозначается отдельно.
- При расхождении складов добавление блокируется. Лимит тестовой корзины не превышает общий остаток и исключает служебные складские записи по консервативному правилу. Это правило прототипа, не подтверждённая логика отгрузки EKT.
- Поиск «25 А» не возвращает автомат 125 А из-за совпадения подстроки.
- Исходная выборка обновлена ответами всех 200 карточек. Дополнительно загруженные в базе страницы имеют собственную дату и обновляются при открытии товара.

## Воспроизведение

`node scripts/audit-api.mjs` создаёт `docs/api-audit.json`. Флаг `--refresh` также обновляет исходную выборку при отсутствии ошибок запросов. Доступ берётся из переменных окружения или игнорируемого `.env`; секреты в отчёт не попадают.

## Границы проверки

Согласованность API не доказывает правильность характеристик производителя или реальное наличие на складе. Спорные позиции требуют ответа EKT. Сертификаты, валюта, единица продажи, условия НДС и отгрузки не выводятся из косвенных полей.
